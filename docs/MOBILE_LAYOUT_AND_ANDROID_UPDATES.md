# 手机布局与 Android 更新验收

适用版本：Windows 2.3.15 / Android 1.1.12。

## 手机布局修复

手机搜索路由位于页头下方，但共享的触控布局又为同一行的账号/视觉按钮减去 164px，且选择器优先级覆盖手机路由宽度。在 420px 页面中，搜索框和平台切换栏仅有 232px。现将该预留空间规则限制到没有启用手机路由的桌面/平板；手机恢复左右各 12px 留白，搜索框、平台切换和结果列表宽度为 396px。

`python checks/check_mobile_layout.py` 启动真实 Android Python 页面适配器并加载真实 Android JS 桥，使用独立临时数据与合成歌曲，原生 Java 接口以测试对象替代。Chromium 覆盖 320×640、360×800、393×852、420×900、600×960 和 844×390 六种尺寸，逐项检查：首页、搜索框/平台栏/长标题结果、音乐库、本地播放、更多播放控制、歌单/队列、登录及更新弹窗。

检查包括横向边界、搜索栏整行宽度、结果列表与底栏间距、末尾平台按钮可滚动到达、播放按钮在视口内、本地音频与歌词导入播放。更新弹窗覆盖发现版本、54% 下载进度、收起后重新打开、下载完成可安装、取消后再次安装和错误提示。六种尺寸均无 JavaScript 异常。这是浏览器布局与桥接界面测试，不等同 Android 系统 WebView 的真机验收。

## Android 原生更新

- `UpdatePolicy` 验证独立 Android 版本号、发布文件名、HTTPS 来源、摘要，以及安装包身份/版本/签名。
- `UpdateTransfer` 流式下载并报告字节进度，限制大小及重定向，下载完整且摘要一致后才移交安装包。
- `AppUpdater` 在进程内保留状态，负责 PackageManager 校验与前台系统安装交接；页面通过原生桥查询和订阅状态。
- `UpdateApkProvider` 只读共享 `cache/updates/update.apk`；安装器获得临时 URI 读取权限。来源授权与安装均通过系统界面完成。

`python -m unittest discover -s Android_apk/checks -p 'test_*.py' -v` 在 JDK 17 下执行生产 Java 下载/校验代码的回归：错误主机、HTTP 降级、错误版本/包名/签名、缺失摘要、超限文件、下载中断、短读、超长内容、摘要失败、进度递增与最终文件原子移交。完整 Gradle 发布构建验证 Android 平台接口与 Manifest，APK 另行验签和对齐。

实际网络检查使用同一 Java HTTPS/重定向/流式写入/摘要代码，从 GitHub 正式发布下载完整 APK 并匹配发布摘要。该检查不安装手机，也不使用真实账号。按用户先前要求，本轮未覆盖安装手机；系统安装界面、来源授权返回和真机后台下载仍需设备验收，不将浏览器模拟或 JDK 测试记为真机通过。

本轮本地回归合计 71 项：共享 Python 30 项、Android Python/Java 20 项、Node 21 项，全部通过且无跳过。Android 更新测试包含 44 个 Java 内部断言；真实下载使用 v2.3.14 的 Android 1.1.11 安装包，共 116,370,749 字节，完整 SHA-256 匹配。

Windows 使用独立测试用户目录，先启动已安装的 2.3.14，再由新构建的 2.3.15 接续同源数据。两版均加载 334 个模块并正常退出；合成账号/歌单、本地音频/歌词和媒体缓存保留，旧界面缓存被定向清理，没有修改日常使用的安装或用户目录。本轮验证成品启动及数据兼容，未重复执行系统覆盖安装。
