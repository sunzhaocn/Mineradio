# Windows 实际安装与自动更新验收

验收日期：2026-10-26。使用本机真实的每用户安装目录和现有用户数据，升级前进行了完整离线备份。未修改 Windows 安全设置。

## 发现的问题

原版 2.3.11 正在运行时，更新入口缺失。实际浏览器读取的缓存脚本只有 958 字节，缺少原生更新接入；安装目录中的脚本已经包含更新功能。旧 Service Worker 缓存使用固定摘要，Windows 打包流程又没有刷新摘要，导致升级后仍可能加载旧页面。

2.3.13 的构建流程为网页建立独立快照，并按文件内容生成缓存摘要。新增回归检查确认脚本变化会改变摘要、旧生成文件不会残留、源码不被改写、未托管目录不会被覆盖。

## 自动更新：2.3.11 → 2.3.12

1. 为单独验证原更新器，先移除播放器自己的旧页面资源缓存；未清除 localStorage、IndexedDB 或账号数据。更新入口恢复并识别到正式发布的 2.3.12。
2. 点击真实界面中的“立即更新”，从 GitHub 下载 405128160 字节的安装包；记录了持续的下载进度、100% 完成、校验完成及进入安装状态。
3. 原 Electron 和后端正常退出，更新器自动启动安装程序，覆盖同一目录。下载文件的 SHA-256 与公开发布包完全一致。
4. 安装后的应用文件版本和 Windows 卸载记录均为 2.3.12；没有自动启动，符合产品设计。重新启动后 334 个界面模块正常加载，更新器识别当前版本。
5. 28 项本地存储全部保留，其中 27 项内容摘要完全一致；唯一变化项是每日推荐缓存。

此流程证明下载、校验、退出、安装及重新启动能够完成；同时确认旧缓存问题必须修复，不能据此声称未修复的旧界面也能直接更新。

## 手动覆盖：2.3.12 → 2.3.13

1. 在真实用户缓存中重新放回触发问题的旧脚本，确认原生更新接入再次缺失。
2. 正常退出播放器，以 `/S` 参数直接运行新安装包；此次为手动启动安装器，不走自动更新器，也未先卸载。
3. 安装器退出码为 0；应用版本与卸载记录均变为 2.3.13，安装目录保持原值。
4. 安装器执行前后，3277 个用户数据文件逐一核对，缺失 0、内容变化 0。
5. 保留旧缓存直接启动新安装：旧资源缓存被自动替换，原生更新接入和更新按钮正常出现，334 个模块加载成功。没有手动清缓存或强制绕过 Service Worker。
6. 三套既有 IndexedDB 数据库仍存在；28 项本地存储无缺项，27 项摘要完全一致，仅每日推荐缓存正常变化。播放器保持暂停状态。
