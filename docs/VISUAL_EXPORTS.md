# 视频、音频、歌词与歌曲预设

版本：Windows 2.3.17 / Android 1.1.14，2026-10-27。

## Windows：生成当前预设的视频

在歌曲的下载菜单中选择“导出视频 · 当前预设”。选择当前预设或该曲已经保存的预设、720p/1080p 和 30/60 帧，然后选择 MP4 保存位置。

视频使用所选歌曲的音频与预设参数，从歌曲开头生成完整画面并合成音乐；不包含播放器按钮，无需播放一遍来录屏。所选歌曲与预设在打开导出面板时固定，后台切歌或改动全局预设不会让任务换成另一首歌。音频必须能够完整读取或由当前平台提供下载，不自动换到其他平台的音源。暂无歌词时只生成画面和音乐。

处理时间取决于预设复杂度、分辨率和本机性能。面板显示进度，可收起后通过“视频导出”按钮重新查看，也可取消。导出在独立窗口进行，不替换当前播放器的音频或进度。取消、损坏音频及编码失败不会覆盖原有目标文件；编码完成后才移交最终 MP4。

支持全部 15 个内置预设，包括内置的“音域回响 Wallpaper Engine”、MV 和幻灯片。MV 使用现有片源；片源结束后遵循循环或回退设置，没有片源时按设定的回退预设生成。优先使用本机已缓存的 MV，避免重复查询和下载。幻灯片保留图片、切换间隔与过渡。

另外导入的外部 Wallpaper Engine 项目依赖其引擎和工程素材，本版不对这些项目进行离线视频导出；会明确提示，避免生成错误的替代画面。普通预设文件可以保存其项目引用，在已配置该项目的 Windows 电脑中重新加载，不包含外部引擎及整个工程。

音频和可选 MV 各限制 512 MiB，音频时长不超过两小时。MP4 编码为 H.264/AAC；单独导出的音频不经过视频转码，保持原文件内容。内置字体使用系统与应用的字体回退，自定义字体随预设携带。

## Windows / Android：分别保存文件

在播放页或歌曲列表的下载菜单中：

- **导出本地音频**：导出已经保存的原音频字节，保留文件格式与扩展名。
- **下载歌词 · LRC**：导出该曲保存的 LRC，包含 UTF-8 BOM，便于 Windows 播放器识别。
- **此曲预设**：保存当前预设到此曲、下载此曲预设、加载此曲预设或导入预设文件到此曲。

普通音质下载仍保持原入口，并尝试把点击下载时的预设和封面一起关联到新保存的歌曲。之后改动全局预设不会覆盖该曲记录；也可以主动重新保存。音频已经保存但预设保存失败时，音频不会删除，可从歌曲的预设菜单重试。

预设文件是 `mineradio-track-preset` schema 1 的 JSON，含参数、相机状态和需要的背景、字体、幻灯片及封面素材，不含账号、Cookie 或 SDK 配置。可从歌曲预设菜单导入并加载；也接受旧的 `mineradio-user-fx-archive` schema 1 作为参数导入。新文件请通过歌曲的预设菜单加载，以保留其中素材。

预设素材文件总大小限制 128 MiB。加载幻灯片使用独立的临时图片集合，不删除或覆盖原有相册；导出时读取实际切换间隔。Android 手机只保存和记住预设参数/素材，维持轻量播放器，不为此启动三维场景；平板仍沿用已有视觉模式。Android 通过系统文件选择器保存文件，Windows 通过保存对话框选位置。

音乐库不再单独显示“本机已保存的音乐”区块；导出与预设管理统一通过歌曲下载菜单进入。账号、歌单、本地音频和歌词的数据格式保持；歌曲预设使用单独的本地数据库。

## 实现与验证

`track-exports.js` 提供歌曲预设关联、文件导入/导出和素材校验；`video-export.js` 处理 Windows 进度界面和所选歌曲的素材读取。`video-exporter.js` 使用随客户端打包的 FFmpeg 分析音频，在独立、无账号的渲染会话中逐帧运行真实预设，再合成 MP4；`export-spectrum.js` 提供固定时刻的 Blackman 窗 FFT，`video-renderer.js` 控制音频时钟、歌词、MV 和背景视频帧。嵌入式网页预设也跟随同一时钟。

渲染页只有最小的只读任务桥，不获得主窗口的文件、账号、更新和窗口管理权限。文件写入需来自可信主窗口并通过保存对话框选择目标；临时文件只在本次任务的专用目录内创建和清理。渲染会话的存储清理不会影响主播放器数据。

验证命令：

```powershell
node --test checks/visual-exports.test.cjs
python -X utf8 Windows_exe/checks/check_video_export.py
python -X utf8 checks/check_export_ui.py
python -X utf8 checks/check_mobile_layout.py
```

真实 Electron/FFmpeg 检查生成 19 段测试视频：全部 15 个内置预设、1080p 60 帧、自定义图片、背景视频和自定义字体。验证 H.264/AAC、尺寸、帧数和音频时序；测试音频与导出音频的相关系数大于 0.98。另验证取消与错误不覆盖现有文件、拒绝并发任务和未授权调用，以及清理临时文件。

桌面 Chromium 的真实导出界面检查所选音频字节、歌词、预设、尺寸及帧率，进度收起/重开、取消、缓存 MV 复用、MV 结束行为及幻灯片素材/间隔往返。Android 页面和实际 JS 桥在六种尺寸下检查音频与歌词导出字节一致、预设关联隔离、文件导入和加载、过滤账号字段。

Windows 打包程序使用隔离配置从 2.3.16 升级到 2.3.17，确认账号、歌单、本地音频、歌词及音乐缓存保留，已导入原文件的导出 SHA-256 一致，视频任务接口按预期校验调用。修复多个自定义媒体通道注册互相覆盖的问题；本地音频、封面及幻灯片通道一次注册，保留原有文件授权校验。

Windows 渲染与编码是在本机真实 Electron 运行；界面保存调用与 Android 原生保存接口使用受控替身。按此前要求，本轮未覆盖安装手机，Android 系统文件选择器仍需真机验收。
