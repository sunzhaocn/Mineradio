# 酷狗 Cookie 应用修复：Android 1.0.2 / Windows 2.2.2

验证日期：2026-10-24。用户反馈同一 Cookie 应用后，原客户端与 Mineradio 都被下线。

## 修复

之前的 `music_app/web/account_profiles.py` 为补齐酷狗昵称、头像，调用了 `login-user.kugou.com/v1/autologin`。保存手动 Cookie、恢复缺失资料时会走到此处。这个登录调用不应出现在可选的资料读取链路中。上一轮只验证了重新应用 Cookie 后曲库能加载，没有覆盖原会话是否继续有效。

本次已删除该自动登录和响应 Cookie 恢复代码。酷狗资料读取只解析当前 Cookie 中已有的公开昵称、头像；不会为补齐资料调用登录、兑换令牌或注册设备。资料不完整时保留 Cookie；重复应用完全相同的 Cookie 时保留原扫码昵称、头像和原始凭据字段；不同 Cookie 不继承旧账号资料。用户主动发起并确认的扫码登录流程保留。

修改已同步到共享 Web、APK 和 Windows 安装包。

## 验证

- 相关 Python 回归检查完整及最简 Cookie：读取资料不发出上游网络请求，Cookie 不被修改；最简 Cookie 缺少昵称或头像时正常保留凭据。
- 真实登录 UI 的隔离回归共 33 个场景，新增重复应用酷狗 Cookie、保留扫码资料、不同 Cookie 隔离和失败不清除会话检查。
- Windows 成品使用独立测试资料和虚构凭据，经真实表单连续应用同一 Cookie 三次：Cookie 原值保留、头像资料保留，每次新增登录请求均为 0；实际打包后端资料接口返回 200，不返回替换后的 Cookie 或凭据。
- 手机正式 APK 使用虚构凭据请求资料接口三次，均返回正常资料，没有替换凭据；不写入用户账号存储。
- 对 APK 内 Python 3.12 字节码检查：酷狗资料函数与当前源码一致，自动恢复函数已移除，资料函数不调用网络接口。
- 手机已覆盖安装 1.0.2 正式包；安装文件 SHA256 与交付包一致。冷启动、本机健康检查、汽水搜索 2 首、榜单 3 项通过，调试接口返回 404。
- Python 全量复验 728 项，5 项跳过，其余通过；50 个前端测试脚本通过。首次并行构建期间有两项本机 HTTP 连接中止，单独复验及随后全量复验均通过。
- Windows 成品运行回归通过；安装包全部嵌入文件 CRC 检查通过，511 个网页文件与本次构建快照一致。APK 从同一快照构建并逐文件比对，防止构建期间工作目录的视觉资源改动造成版本不一致。Windows 已覆盖升级 2.2.2，保留原数据目录。

## 验证边界

本次使用隔离凭据验证禁止隐式登录的行为，未拿真实账号再触发登录来尝试复现顶号。**尚未完成官方 App 与修复版使用真实新会话共存的复验，不应把隔离测试称作该项已实测通过。** 已被平台注销的旧 Cookie 无法靠本机修复重新生效，仍需取得有效的新凭据；本次没有擅自重新登录或清除账号。

缺少昵称、头像的最简 Cookie 使用已有资料或默认显示，不再为了补齐资料自动登录。上一版播放器、下载、手机/平板布局的详细实测保留在 `验证报告-1.0.1.md`，对应历史机器记录为 `verification-1.0.1.json`。
